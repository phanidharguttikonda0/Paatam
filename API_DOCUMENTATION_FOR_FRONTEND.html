⚡ Asynchronous Workflows & Frontend State Synchronization Guide
AWS SQS + Lambda Serverless Architecture (No Timeout Latency)

All heavy AI tasks (PDF OCR, Question Paper Extraction, Bulk Stack Slicing, and Rubric Grading) run asynchronously in the background via dedicated AWS SQS queues and Lambda workers. The REST API responds instantly (<100ms) with tracking IDs. Follow the status transitions below to implement real-time progress bars and automated polling in the frontend.

📄 Assignment Paper & Key Ingestion

  • Trigger: POST /api/assignments/process-async
  • State 1: ocr_processing — Lambda runs Vision OCR (Sarvam/Gemini) to extract hierarchical questions & rubric keys. Render a progress bar at 45%.
  • State 2: ready — Extraction complete. Questions & answer key text are populated. Progress hits 100%.
  • Polling: Poll GET /api/assignments/:id/pipeline-status every 3 seconds until ready.

📦 Bulk Class Stack Splitting

  • Trigger: POST /api/submissions/bulk (35-student PDF)
  • State 1: queued → splitting — Lambda scans page headers, names, and QR codes to slice the multi-page stack into individual student PDFs.
  • State 2: grading — Sliced papers are enqueued to the OCR and Evaluation workers. Submissions start appearing in the review table.
  • State 3: completed — All student submissions generated.
  • Polling: Poll GET /api/submissions/batch/:jobId every 5 seconds.

✍️ Student Paper Evaluation & Grading

  • Trigger: Student upload or Bulk Stack slice
  • Stage 1: ocr_processing — Lambda transcribes handwritten answers line-by-line (Indic via Sarvam DocAI, STEM via Gemini).
  • Stage 2: evaluating — Rubric scoring, ground truth comparison, and Socratic hint synthesis via LLM reasoning.
  • Terminal: graded / pending_review — Marks & feedback published. Student receives scorecard notification.
  • Polling: Poll GET /api/submissions/:id every 4 seconds.
